# سیستم نوبت‌دهی آنلاین

سیستم رزرو نوبت برای کسب‌وکارهای خدماتی (آرایشگاه، کلینیک، مشاوره و …) با **تقویم شمسی**، **رابط فارسی راست‌چین**، **پنل مدیریت**، **پیامک تأیید و یادآوری** و **پرداخت آنلاین (بیعانه یا کل مبلغ)**.

## راه‌اندازی سریع

نیازمند Node.js نسخهٔ ۲۲٫۱۳ یا بالاتر (دیتابیس SQLite داخل خود Node است و چیز دیگری نصب نمی‌شود).

```bash
npm install
npm run seed-demo   # (اختیاری) داده‌های نمونه + مدیر آزمایشی
npm start
```

- صفحهٔ رزرو مشتری: <http://localhost:3000>
- پنل مدیریت: <http://localhost:3000/admin/>

`seed-demo` اطلاعات ورود مدیر آزمایشی را در `data/demo-credentials.txt` می‌نویسد.
برای استفادهٔ واقعی به‌جای آن حساب مدیر خودتان را بسازید (گذرواژه پنهان وارد می‌شود):

```bash
npm run create-admin
```

همین دستور برای **بازنشانی گذرواژهٔ فراموش‌شده** هم کار می‌کند (با همان نام کاربری).

## شروع کار بعد از نصب

در پنل مدیریت به‌ترتیب:

1. **تنظیمات**: نام کسب‌وکار، تلفن، نشانی و رنگ سایت.
2. **خدمات**: خدمت‌ها را با مدت زمان و قیمت تعریف کنید.
3. **پرسنل**: هر نفر را بسازید، خدماتی را که انجام می‌دهد تیک بزنید و ساعت کاری هفتگی‌اش را تنظیم کنید (چند بازه در روز، مثلاً صبح و عصر، پشتیبانی می‌شود).
4. **مرخصی و تعطیلات**: تعطیلی‌ها و مرخصی‌ها (تمام روز یا ساعتی، برای یک نفر یا کل مجموعه).

بعد از این‌ها، لینک صفحهٔ رزرو را در اینستاگرام، گوگل‌مپ یا وب‌سایت‌تان بگذارید.

## قابلیت‌ها

**مشتری**
- انتخاب خدمت ← پرسنل (یا «هر کدام») ← روز و ساعت از تقویم شمسی ← ثبت با نام و موبایل
- زمان‌های خالی لحظه‌ای محاسبه می‌شوند (ساعت کاری − مرخصی − نوبت‌های دیگر − زمان استراحت بین نوبت‌ها)
- کد پیگیری و صفحهٔ مشاهده/لغو نوبت (`/b/کد`)
- پرداخت آنلاین؛ زمان انتخاب‌شده در مدت «مهلت پرداخت» برای مشتری نگه داشته می‌شود و بعد آزاد می‌شود

**مدیر**
- فهرست نوبت‌های هر روز، جستجو (نام، موبایل، کد)، ثبت دستی نوبت (با ساعت دلخواه)، جابه‌جایی، تغییر وضعیت (انجام شد / عدم حضور / لغو)، ثبت پرداخت نقدی
- مدیریت خدمات، پرسنل، ساعت کاری، مرخصی، مشتریان (با سابقه و یادداشت) و گزارش پیامک‌ها
- هشدار هنگام ثبت مرخصی اگر در آن بازه نوبت فعال وجود داشته باشد

**قوانین قابل تنظیم**: فاصلهٔ زمان‌های پیشنهادی، حداقل فاصله تا نوبت، حداکثر روزهای آینده، مهلت لغو آنلاین، حداکثر نوبت فعال برای هر شماره، متن قوانین لغو.

## پیامک و پرداخت

هر دو به‌طور پیش‌فرض روی حالت **آزمایشی** هستند تا بدون کلید و بدون هزینه بتوانید همه‌چیز را امتحان کنید:

| بخش | حالت آزمایشی | حالت واقعی |
|---|---|---|
| پیامک | پیام‌ها فقط در «پیامک‌ها» ثبت می‌شوند | کاوه‌نگار (کلید API و شمارهٔ خط) |
| پرداخت | صفحهٔ درگاه شبیه‌سازی‌شده (پول واقعی نمی‌گیرد) | زرین‌پال (مرچنت‌کد) |

برای فعال‌سازی: پنل مدیریت ← **تنظیمات** ← بخش «پیامک» یا «پرداخت آنلاین».
کلیدها بعد از ذخیره هرگز دوباره به مرورگر برگردانده نمی‌شوند.

> **مهم:** آداپتورهای کاوه‌نگار و زرین‌پال بر اساس مستندات عمومی آن‌ها نوشته شده‌اند، اما در توسعه کلید واقعی در دسترس نبود و با سرویس زنده آزمایش **نشده‌اند**. پیش از راه‌اندازی عمومی، یک پیامک و یک پرداخت کوچک واقعی (یا محیط آزمایشی زرین‌پال) را امتحان کنید.
> هنگام استفاده از «بیعانه»، حتماً درگاه را از «آزمایشی» به «زرین‌پال» تغییر دهید؛ در حالت آزمایشی هر کسی بدون پرداخت واقعی نوبت قطعی می‌کند.

بازپرداخت وجه (مثلاً هنگام لغو نوبت پرداخت‌شده) خودکار نیست و باید از پنل درگاه انجام شود. در صفحهٔ لغو نوبت، مبلغ پرداخت‌شده به مدیر نشان داده می‌شود.

## راه‌اندازی روی سرور

یک فایل `.env` (روی نمونهٔ `.env.example`) بسازید:

| متغیر | توضیح |
|---|---|
| `PORT` | پورت (پیش‌فرض ۳۰۰۰) |
| `BASE_URL` | **آدرس عمومی سایت** مثل `https://reserve.example.ir`؛ برای بازگشت از درگاه پرداخت و لینک پیامک لازم است |
| `COOKIE_SECURE` | پشت HTTPS مقدار `true` بگذارید |
| `TRUST_PROXY` | پشت Nginx/Cloudflare عدد `1` بگذارید تا IP واقعی کاربر برای محدودیت تعداد درخواست خوانده شود |
| `DB_PATH` | مسیر فایل دیتابیس (پیش‌فرض `data/reservation.db`) |

- دیتابیس یک فایل است (`data/reservation.db`)؛ برای پشتیبان‌گیری همین فایل را کپی کنید (بهتر است سرور هنگام کپی خاموش باشد یا از `sqlite3 .backup` استفاده کنید).
- برنامه باید پشت HTTPS اجرا شود (مثلاً با Nginx یا Caddy) و با pm2/systemd زنده بماند.
- یادآوری‌ها و آزادسازی نوبت‌های پرداخت‌نشده توسط یک زمان‌بند داخلی هر دقیقه اجرا می‌شود؛ برنامه را فقط در **یک** پردازش اجرا کنید.
- ساعت‌ها به وقت منطقهٔ زمانی تنظیم‌شده (پیش‌فرض `Asia/Tehran`) ذخیره و نمایش داده می‌شوند.

## ساختار پروژه

```
server/
  index.js, app.js, db.js, config.js
  lib/        availability.js (محاسبهٔ زمان خالی)، booking.js (ثبت/لغو/ویرایش)،
              payment.js، sms.js، scheduler.js، settings.js، auth.js، jalali.js …
  routes/     public.js (مشتری)، admin.js (مدیر)، pay.js (درگاه)
public/       رابط کاربری بدون بیلد (ES modules)؛ فونت وزیرمتن داخل پروژه است
scripts/      create-admin.js، seed-demo.js
test/         تست‌های خودکار (npm test)
```

## تست

```bash
npm test
```

شامل تست محاسبهٔ زمان خالی، جلوگیری از رزرو دوبل، مهلت پرداخت، جریان درگاه، تبدیل تاریخ شمسی، ورود مدیر و مسیرهای API است.

## امنیت

- گذرواژه با scrypt هش می‌شود؛ نشست‌ها با توکن تصادفی در کوکی `HttpOnly` + `SameSite=Lax` و در دیتابیس به‌صورت هش ذخیره می‌شوند
- محدودیت تلاش ورود، محدودیت ثبت نوبت در ساعت برای هر IP و سقف نوبت فعال برای هر شماره
- فقط درخواست‌های JSON اجازهٔ تغییر داده دارند (دفاع در برابر CSRF) و CSP سخت‌گیرانه (بدون اسکریپت inline)
- رابط کاربری هیچ داده‌ای را با `innerHTML` وارد صفحه نمی‌کند (جلوگیری از XSS)
- کد پیگیری ۸ کاراکتری تصادفی است و صفحهٔ پیگیری شمارهٔ موبایل مشتری را نشان نمی‌دهد

## محدودیت‌های فعلی

- تأیید شمارهٔ موبایل با کد پیامکی (OTP) ندارد؛ برای جلوگیری از رزرو الکی از سقف نوبت فعال و پرداخت بیعانه استفاده کنید
- مشتری نمی‌تواند نوبت را خودش جابه‌جا کند (لغو و رزرو دوباره یا تماس با مدیر)
- یک نقش مدیر دارد (بدون سطح دسترسی جداگانه برای منشی/پرسنل)
- بازپرداخت خودکار ندارد
