# سیستم نوبت‌دهی آنلاین

سیستم رزرو نوبت برای کسب‌وکارهای خدماتی (آرایشگاه، کلینیک، مشاوره و …) با **تقویم شمسی**، **رابط فارسی راست‌چین**، **پنل مدیریت**، **پیامک تأیید و یادآوری** و **پرداخت آنلاین (بیعانه یا کل مبلغ)**.

## راه‌اندازی سریع

نیازمند Node.js نسخهٔ ۲۲٫۱۳ یا بالاتر (دیتابیس SQLite داخل خود Node است و چیز دیگری نصب نمی‌شود).

```bash
npm install
npm run seed-demo   # (اختیاری) داده‌های نمونه + مدیر آزمایشی
npm start
```

- صفحهٔ رزرو مشتری: <http://localhost:3000>
- پنل مدیریت: <http://localhost:3000/admin/>

`seed-demo` اطلاعات ورود مدیر آزمایشی را در `data/demo-credentials.txt` می‌نویسد.
برای استفادهٔ واقعی به‌جای آن، حساب **مدیر کل** خودتان را بسازید (گذرواژه پنهان وارد می‌شود؛ حداقل ۱۰ حرف):

```bash
npm run create-admin
```

همین دستور مسیر **بازیابی** هم هست: اگر گذرواژهٔ مدیر کل را فراموش کردید یا حسابش غیرفعال شد، با همان نام کاربری دوباره اجرایش کنید؛ گذرواژه عوض می‌شود، حساب فعال می‌شود و همهٔ نشست‌های قبلی بسته می‌شود.

> قبل از راه‌اندازی عمومی، اگر `seed-demo` را اجرا کرده‌اید، حساب **`demo`** را از «کاربران و امنیت» غیرفعال کنید.

## شروع کار بعد از نصب

در پنل مدیریت به‌ترتیب:

1. **تنظیمات**: نام کسب‌وکار، تلفن، نشانی و رنگ سایت.
2. **خدمات**: خدمت‌ها را با مدت زمان و قیمت تعریف کنید.
3. **پرسنل**: هر نفر را بسازید، خدماتی را که انجام می‌دهد تیک بزنید و ساعت کاری هفتگی‌اش را تنظیم کنید (چند بازه در روز، مثلاً صبح و عصر، پشتیبانی می‌شود).
4. **مرخصی و تعطیلات**: تعطیلی‌ها و مرخصی‌ها (تمام روز یا ساعتی، برای یک نفر یا کل مجموعه).

بعد از این‌ها، لینک صفحهٔ رزرو را در اینستاگرام، گوگل‌مپ یا وب‌سایت‌تان بگذارید.

## قابلیت‌ها

**مشتری**
- انتخاب خدمت ← پرسنل (یا «هر کدام») ← روز و ساعت از تقویم شمسی ← ثبت با نام و موبایل
- زمان‌های خالی لحظه‌ای محاسبه می‌شوند (ساعت کاری − مرخصی − نوبت‌های دیگر − زمان استراحت بین نوبت‌ها)
- کد پیگیری و صفحهٔ مشاهده/لغو نوبت (`/b/کد`)
- پرداخت آنلاین؛ زمان انتخاب‌شده در مدت «مهلت پرداخت» برای مشتری نگه داشته می‌شود و بعد آزاد می‌شود

**مدیر**
- فهرست نوبت‌های هر روز، جستجو (نام، موبایل، کد)، ثبت دستی نوبت (با ساعت دلخواه)، جابه‌جایی، تغییر وضعیت (انجام شد / عدم حضور / لغو)، ثبت پرداخت نقدی
- مدیریت خدمات، پرسنل، ساعت کاری، مرخصی، مشتریان (با سابقه و یادداشت) و گزارش پیامک‌ها
- هشدار هنگام ثبت مرخصی اگر در آن بازه نوبت فعال وجود داشته باشد

**قوانین قابل تنظیم**: فاصلهٔ زمان‌های پیشنهادی، حداقل فاصله تا نوبت، حداکثر روزهای آینده، مهلت لغو آنلاین، حداکثر نوبت فعال برای هر شماره، متن قوانین لغو.

## ورود، نقش‌ها و کاربران پنل

همهٔ داده‌های پنل پشت ورود با نام کاربری و گذرواژه هستند. بدون ورود، هر مسیر `/api/admin/*` پاسخ ۴۰۱ می‌دهد و حتی کد صفحه‌های داخلی پنل (`/admin/pages/*`) ارسال نمی‌شود؛ فقط پوستهٔ صفحهٔ ورود باز است.

| نقش | دسترسی |
|---|---|
| **مدیر کل** | همه‌چیز: نوبت‌ها، مشتریان، خدمات، پرسنل، مرخصی، پیامک‌ها، تنظیمات، کاربران و گزارش امنیتی |
| **منشی** | فقط «نوبت‌ها» و «مشتریان» (ثبت، ویرایش و لغو نوبت). سرور بقیهٔ بخش‌ها را با ۴۰۳ می‌بندد، نه فقط منو |

مدیر کل در **کاربران و امنیت** برای هر نفر حساب جداگانه می‌سازد (به‌جای اشتراک یک گذرواژه):
- گذرواژهٔ تعیین‌شده توسط مدیر **موقتی** است؛ کاربر در اولین ورود باید گذرواژهٔ شخصی بگذارد و تا آن موقع به هیچ بخشی دسترسی ندارد.
- غیرفعال‌سازی یا تغییر نقش، **فوراً** نشست‌های باز آن کاربر را می‌بندد.
- بازنشانی گذرواژهٔ دیگران، نشست‌هایشان را می‌بندد و دوباره تغییر اجباری می‌شود.
- مدیر نمی‌تواند نقش یا وضعیت حساب خودش را تغییر دهد (جلوگیری از قفل شدن همه).

هر کاربر از «حساب من» می‌تواند گذرواژه‌اش را عوض کند یا از دستگاه‌های دیگر خارج شود.

**سخت‌گیری‌های ورود**
- گذرواژه: حداقل ۱۰ حرف، بدون نام کاربری، نه ساده و تکراری (هش با scrypt)
- محدودیت تلاش ناموفق (۱۵ دقیقه) در **سه لایه**: هر (IP + نام کاربری) ۱۰ بار، هر نام کاربری از مجموع همهٔ IPها ۲۰ بار (جلوی حملهٔ توزیع‌شده با IPهای مختلف روی یک حساب را می‌گیرد) و هر IP روی همهٔ نام‌ها ۶۰ بار
- نشست با کوکی `HttpOnly` و `SameSite=Strict`؛ ۸ ساعت بی‌فعالیتی یا ۷ روز از ورود، هرکدام زودتر، نشست را می‌بندد
- پیام خطای ورود برای «کاربر ناموجود»، «گذرواژهٔ غلط» و «حساب غیرفعال» یکی است و زمان پاسخ هم یکسان
- **گزارش امنیتی** (فقط مدیر کل): ورودهای موفق و ناموفق (با IP)، تغییر گذرواژه و حساب‌ها، تغییر تنظیمات (فقط نام کلیدها، نه مقدار) و رویدادهای لغو نوبت توسط مشتری

## لغو نوبت توسط مشتری (تأیید هویت با پیامک)

کد پیگیری به‌تنهایی **برای لغو کافی نیست**. چون ممکن است کد در اختیار شخص دیگری قرار گرفته باشد:

1. مشتری «لغو نوبت» را می‌زند؛ یک **کد ۶ رقمی** به شمارهٔ موبایل **ثبت‌شده در خود نوبت** پیامک می‌شود (نه شماره‌ای که درخواست‌دهنده بگوید).
2. کد را وارد می‌کند و نوبت لغو می‌شود.

قوانین کد: ۵ دقیقه اعتبار؛ یک‌بار مصرف؛ بعد از ۵ حدس اشتباه باطل می‌شود؛ فاصلهٔ ۶۰ ثانیه بین دو ارسال و حداکثر ۵ ارسال در ساعت برای هر نوبت؛ هر کد فقط برای همان نوبت معتبر است. خود کد در گزارش پیامک‌ها ذخیره نمی‌شود (به‌جایش `••••••` می‌آید).

صفحهٔ عمومی پیگیری هم دیگر **نام مشتری** را نشان نمی‌دهد و فقط شمارهٔ ماسک‌شده (`۰۹۱۲***۶۷۸۹`) را می‌بیند.

> **بدون پیامک، لغو آنلاین بسته است.** اگر ارسال پیامک خاموش باشد، راه امنی برای تأیید هویت وجود ندارد؛ به‌جای باز گذاشتن لغو بدون تأیید، به مشتری گفته می‌شود تماس بگیرد. برای فعال بودن لغو آنلاین، پیامک را روشن کنید و **کاوه‌نگار** را تنظیم کنید. در حالت «آزمایشی» کد فقط در کنسول سرور چاپ می‌شود و به مشتری نمی‌رسد.

## پیامک و پرداخت

هر دو به‌طور پیش‌فرض روی حالت **آزمایشی** هستند تا بدون کلید و بدون هزینه بتوانید همه‌چیز را امتحان کنید:

| بخش | حالت آزمایشی | حالت واقعی |
|---|---|---|
| پیامک | پیام‌ها فقط در «پیامک‌ها» ثبت می‌شوند | کاوه‌نگار (کلید API و شمارهٔ خط) |
| پرداخت | صفحهٔ درگاه شبیه‌سازی‌شده (پول واقعی نمی‌گیرد) | زرین‌پال (مرچنت‌کد) |

برای فعال‌سازی: پنل مدیریت ← **تنظیمات** ← بخش «پیامک» یا «پرداخت آنلاین».
کلیدها بعد از ذخیره هرگز دوباره به مرورگر برگردانده نمی‌شوند.

> **مهم:** آداپتورهای کاوه‌نگار و زرین‌پال بر اساس مستندات عمومی آن‌ها نوشته شده‌اند، اما در توسعه کلید واقعی در دسترس نبود و با سرویس زنده آزمایش **نشده‌اند**. پیش از راه‌اندازی عمومی، یک پیامک و یک پرداخت کوچک واقعی (یا محیط آزمایشی زرین‌پال) را امتحان کنید.
> هنگام استفاده از «بیعانه»، حتماً درگاه را از «آزمایشی» به «زرین‌پال» تغییر دهید؛ در حالت آزمایشی هر کسی بدون پرداخت واقعی نوبت قطعی می‌کند.

بازپرداخت وجه (مثلاً هنگام لغو نوبت پرداخت‌شده) خودکار نیست و باید از پنل درگاه انجام شود. در صفحهٔ لغو نوبت، مبلغ پرداخت‌شده به مدیر نشان داده می‌شود.

## راه‌اندازی روی سرور

یک فایل `.env` (روی نمونهٔ `.env.example`) بسازید:

| متغیر | توضیح |
|---|---|
| `PORT` | پورت (پیش‌فرض ۳۰۰۰) |
| `BASE_URL` | **آدرس عمومی سایت** مثل `https://reserve.example.ir`؛ برای بازگشت از درگاه پرداخت و لینک پیامک لازم است |
| `COOKIE_SECURE` | پشت HTTPS مقدار `true` بگذارید |
| `TRUST_PROXY` | پشت Nginx/Cloudflare عدد `1` بگذارید تا IP واقعی کاربر برای محدودیت تعداد درخواست خوانده شود |
| `DB_PATH` | مسیر فایل دیتابیس (پیش‌فرض `data/reservation.db`) |

- دیتابیس یک فایل است (`data/reservation.db`)؛ برای پشتیبان‌گیری همین فایل را کپی کنید (بهتر است سرور هنگام کپی خاموش باشد یا از `sqlite3 .backup` استفاده کنید).
- برنامه باید پشت HTTPS اجرا شود (مثلاً با Nginx یا Caddy) و با pm2/systemd زنده بماند.
- یادآوری‌ها و آزادسازی نوبت‌های پرداخت‌نشده توسط یک زمان‌بند داخلی هر دقیقه اجرا می‌شود؛ برنامه را فقط در **یک** پردازش اجرا کنید.
- ساعت‌ها به وقت منطقهٔ زمانی تنظیم‌شده (پیش‌فرض `Asia/Tehran`) ذخیره و نمایش داده می‌شوند.

```
  index.js, app.js, db.js, config.js
  lib/        availability.js (محاسبهٔ زمان خالی)، booking.js (ثبت/لغو/ویرایش)،
              auth.js (گذرواژه، نشست، نقش‌ها)، otp.js (کد تأیید لغو)، audit.js (گزارش امنیتی)،

  routes/     public.js (مشتری)، admin.js (مدیر)، pay.js (درگاه)

test/         تست‌های خودکار (npm test)
```

## تست

```bash
npm test
```

شامل تست محاسبهٔ زمان خالی، جلوگیری از رزرو دوبل، مهلت پرداخت، جریان درگاه، تبدیل تاریخ شمسی، مسیرهای API، **نقش‌ها و دسترسی‌ها، نشست و محدودیت ورود، کد تأیید لغو نوبت** و مهاجرت دیتابیس قدیمی است.

## امنیت (خلاصه)

- ورود، نقش‌ها، محدودیت تلاش و گزارش امنیتی: بخش «ورود، نقش‌ها و کاربران پنل» بالا
- لغو نوبت با کد تأیید پیامکی: بخش «لغو نوبت توسط مشتری» بالا
- فقط درخواست‌های JSON اجازهٔ تغییر داده دارند (دفاع در برابر CSRF) و CSP سخت‌گیرانه (بدون اسکریپت inline)
- رابط کاربری هیچ داده‌ای را با `innerHTML` وارد صفحه نمی‌کند (جلوگیری از XSS)
- کد پیگیری ۸ کاراکتری تصادفی است
- **پشت پروکسی (Nginx/Cloudflare) حتماً `TRUST_PROXY=1` بگذارید.** وگرنه همهٔ کاربران یک IP دیده می‌شوند و محدودیت‌های هر-IP برای همه مشترک می‌شود.

## محدودیت‌های فعلی

- شمارهٔ موبایل **هنگام ثبت نوبت** با کد پیامکی تأیید نمی‌شود؛ کسی می‌تواند با شمارهٔ دیگران نوبت بگیرد (صاحب شماره می‌تواند با کد پیامکی آن را لغو کند). برای جلوگیری از رزرو الکی از سقف نوبت فعال و پرداخت بیعانه استفاده کنید
- مشتری نمی‌تواند نوبت را خودش جابه‌جا کند (لغو با کد تأیید و رزرو دوباره، یا تماس با مدیر)
- ورود مدیر دو مرحله‌ای (کد پیامکی یا برنامهٔ احراز هویت) ندارد
- محدودیت‌های تعداد درخواست در حافظهٔ همان پردازش نگه‌داری می‌شوند (با ری‌استارت صفر می‌شوند)
- بازپرداخت خودکار ندارد
